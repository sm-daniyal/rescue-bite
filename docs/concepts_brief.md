## Overview

RescueBite (**Swiggy Campus Rescue**) is a two-sided surplus food distress marketplace built for the Swiggy ecosystem. It matches scheduled college break windows with perishable restaurant inventory surplus within a 7 km service radius (5 km core JNNCE focus) of campus. The system applies dynamic pricing recommendations generated by Google Gemini Flash (`25%–65%` bounds, `40%` fallback) and coordinates time-locked self-pickup holds (`30` minutes) over Server-Sent Events (SSE).

The shipped simulation reflects authentic producer/consumer/evaluator separation across three dedicated web routes:
1. **Student Consumer App (`/`) — Mobile-First PWA**: Designed primarily for mobile phone viewports (`360–430px`, `h-dvh`, sticky bottom tab bar, `44px+` tap targets, home-screen install manifest) used between lectures, while scaling cleanly to desktop (`>= 768px`) with left rail navigation and 3-column break layout.
2. **Restaurant Partner POS Terminal (`/partner`)**: Dark-theme kitchen counter terminal (`PartnerTerminal.tsx`), focusing strictly on incoming hold verification, `10`-minute confirmation SLAs, auditable rejection reason codes (`item_unavailable`, `quantity_reduced`, `kitchen_closed`, `other`), pickup completion, and reliability scoring.
3. **Judge Walkthrough & Telemetry Console (`/demo`)**: Isolated evaluation harness (`DemoConsole.tsx`) allowing competition judges to trigger pre-cached Scenarios A, B, and C without polluting consumer or merchant views and inspect live SSE event latency.

## Analysis

### 1. Form Factor & Viewport Ergonomics
- **The Student Persona**: Over 90% of college meal decisions occur on smartphones during short transition windows between lectures.
  - **Mobile Layout Contract (`< 768px`, `StudentApp.tsx`)**:
    - Fixed bottom navigation bar (`Flash Deals`, `Schedule`, `My Holds`, `Impact`) with `pb-[env(safe-area-inset-bottom)]`.
    - Single-column card feed (`DealCard.tsx`) with `>= 44px` tap targets (`Reserve Hold`, search toggle), Fuel Math savings (`-₹12` fuel offset), and veg/category filtering.
    - Sticky orange `BreakBellBanner` on Scenario B / break-bell events with `View` jump to deals.
  - **Desktop Layout Contract (`>= 768px`, `StudentApp.tsx`)**:
    - Persistent inline left rail navigation + top search/student navbar + 3-column break-slot grid (`Morning Tiffin`, `Lunch Break`, `Evening Snacks`) + Radix `BreakBellToast`.

### 2. Dedicated Route Architecture (Producer vs. Consumer Isolation)
Monolithic split-screen prototype components (`App.tsx`, `StudentFeed.tsx`, `RestaurantDashboard.tsx`, `DemoSwitcher.tsx`) were retired in favor of clean separation:
- **Route `/` (`StudentApp.tsx`)**: Pure student discovery feed, schedule alignment, hold tracking, and sustainability ledger. Zero merchant controls or emojis.
- **Route `/partner` (`PartnerTerminal.tsx`)**: 8-outlet partner selector, live discounted `₹` prices, incoming reservation queue with SSE deduplication, and inline auditable rejection reason selector.
- **Route `/demo` (`DemoConsole.tsx`)**: 1-click deterministic execution for Scenarios A, B, and C (`POST /demo/trigger-scenario/{A|B|C}`), API health/deal snapshot (`GET /`, `GET /deals`), and live `/sse/student/1` telemetry stream with latency badges.

### 3. Hosting & Infrastructure Constraints
Evaluating **GitHub Pages (`github.io`)** and **Render Free Tier** identified operational failure modes:
- **GitHub Pages (`github.io`) — REJECTED**: Static-only hosting; cannot run Python/FastAPI, SQLite/PostgreSQL, or persistent Server-Sent Events (SSE).
- **Render Free Tier — REJECTED**: Spins down web services after 15 minutes of inactivity, introducing `50–90s` cold-start latency that interrupts judge walkthroughs and severs SSE streams.
- **Approved Simulation Hosting Stack**:
  - **Frontend**: **Vercel** ([vercel.json](file:///D:/RescueBite/frontend/vercel.json) SPA rewrites for `/partner` and `/demo`, `VITE_API_BASE_URL`).
  - **Backend API**: **Railway** ([railway.toml](file:///D:/RescueBite/backend/railway.toml) + [Procfile](file:///D:/RescueBite/backend/Procfile), Nixpacks, `healthcheckPath = "/"`, zero inactivity sleep).
  - **Database**: SQLite (`sqlite+aiosqlite:///./rescuebite_dev.db`) for simulation deployment; PostgreSQL (`asyncpg`) + Alembic planned for commercial production.

### 4. Concurrency & Scaling Reality (Simulation vs. Real World)
- Current backend supports concurrent student and merchant SSE browser tabs per ID via `asyncio.Queue` sets in `sse_dispatcher.py`, and pre-caches Scenario A/B/C Gemini outputs in `demo_scenarios.yaml`.
- Scaling to `1,000+` concurrent students at live break bell moves to **Stage B (Real-World Graduation)**: multi-worker Redis Pub/Sub / Supabase Realtime SSE fan-out, persistent APScheduler mounted in `main.py` lifespan, PostgreSQL row-level locks (`SELECT ... FOR UPDATE`), OTP/JWT auth, UPI commitment holds, and FCM push alerts.

## Alternatives Weighed

| Alternative | Technical Flaw & Rejection Reason |
|---|---|
| **GitHub Pages (`github.io`) for Full App** | **Rejected**: Static only; cannot host FastAPI, databases, or SSE connections. |
| **Render Free Tier for Backend** | **Rejected**: 15-minute inactivity spin-down triggers 50–90s cold starts during live demos. |
| **Monolithic Split-Screen Interface (`App.tsx`)** | **Rejected & Replaced**: Mixed student and merchant workflows on one screen and degraded mobile layout. |
| **WebSocket Bidirectional Protocol** | **Rejected**: Sticky-session overhead unnecessary for server-to-client push; SSE reconnects natively. |
